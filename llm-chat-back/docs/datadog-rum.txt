# Datadog Real User Monitoring

## RUM이 수집하는 정보
Datadog RUM은 실제 사용자의 페이지 View, 클릭 Action, Resource 요청, Long Task, Error를 연결해 사용자 경험을 분석한다. 서비스, 환경, 버전 값을 프런트 배포와 일관되게 설정하면 릴리스별 성능과 오류를 비교할 수 있다.

View는 사용자가 본 페이지와 로딩 성능을, Action은 클릭과 같은 사용자 행동을, Resource는 fetch/XHR과 정적 파일 요청을 나타낸다. Error 이벤트는 브라우저 오류와 처리되지 않은 예외를 분석하는 데 사용한다. Session은 같은 사용자의 연속된 탐색 흐름을 묶는다.

## RUM과 APM 연결
Browser SDK의 allowedTracingUrls에 백엔드 Origin을 정확히 지정하면 RUM Resource와 백엔드 APM Trace를 연결할 수 있다. 백엔드 CORS는 x-datadog-trace-id, traceparent, tracestate 등 필요한 Header를 허용해야 한다. 상대 경로 정규식만 넓게 허용하면 의도하지 않은 외부 주소로 Trace Header가 전달될 수 있으므로 명시적인 Origin을 권장한다.

## Session Replay와 개인정보
Session Replay는 사용자의 화면 탐색을 재생해 오류 전후의 행동을 이해하는 기능이다. 입력값과 민감한 요소는 개인정보 보호 설정으로 마스킹해야 한다. toy-chat은 기본 개인정보 수준을 mask-user-input으로 사용하고 필요한 요소에는 data-dd-privacy 속성을 적용한다.

## Browser SDK v7과 Source Map
toy-chat은 Datadog Browser SDK v7을 사용한다. RUM, Browser Logs, React 통합 패키지의 버전을 동일하게 유지한다. 프로덕션 오류의 Minified Stack을 원본 App.jsx 위치로 복원하려면 Vite가 만든 Source Map을 RUM의 service, version, minified URL prefix와 동일한 값으로 업로드해야 한다.

node --enable-source-maps는 Node.js 백엔드 Stack을 위한 옵션이며 브라우저 Source Map을 Datadog에 업로드하지 않는다. npm run dev의 소스는 비압축 개발 코드이므로 실제 Source Map 검증은 npm run release:rum과 npm run preview:rum으로 만든 프로덕션 번들에서 수행한다.
