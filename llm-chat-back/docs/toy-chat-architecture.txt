# toy-chat 애플리케이션 구조

## 전체 구성
toy-chat은 React/Vite 프런트엔드와 Node.js/Express 백엔드로 구성된 Datadog 데모 애플리케이션이다. 프런트 기본 주소는 http://localhost:5173이고 백엔드는 http://localhost:3001이다. MySQL은 사용자, 대화, 메시지를 저장한다.

프런트 서비스 이름은 shlim-toy-chat-front이고 백엔드 서비스 이름은 shlim-toy-chat-api다. Browser RUM, Browser Logs, APM, 백엔드 JSON Logs, LLM Observability를 사용해 사용자 요청부터 Provider 응답까지 연결한다.

## 인증과 대화
사용자는 회원가입 또는 로그인 후 JWT를 발급받는다. /chat, /conversations와 사용자 데이터 API는 Bearer Token으로 인증한다. 대화는 사용자별로 분리하며 conversationId가 다른 사용자의 대화인지 서버에서 검증한다.

메시지는 user, assistant, tool 역할로 저장한다. Provider 응답 메타데이터에는 status, provider, model, token, latency, retrieval 정보와 request_id가 포함된다. 실패한 Provider 메시지는 화면 복원을 위해 저장할 수 있지만 다음 LLM Prompt의 대화 이력에는 status=success인 같은 Provider 답변만 포함한다.

## Provider 장애 대응
OPENAI_API_KEY가 있으면 OpenAI Provider를 활성화한다. AZURE_OPENAI_API_KEY와 AZURE_OPENAI_ENDPOINT가 모두 있으면 Azure AI Provider를 활성화한다. 둘 중 하나 이상만 설정되어도 서버를 시작할 수 있다.

활성화된 Provider만 요청한다. 두 Provider가 모두 성공하면 success, 하나만 성공하면 partial_success, 활성 Provider가 모두 실패하면 failed로 처리한다. partial_success는 HTTP 200으로 정상 답변을 표시하고 실패한 Provider 카드에만 안전한 오류 정보를 보여준다.

## RAG 흐름
llm-chat-back/docs의 txt 또는 md 문서를 제목과 Section 경계를 보존해 Chunk로 나눈다. OpenAI Embedding을 사용할 수 있으면 문서 Embedding을 data/rag-cache.json에 캐시한다. 문서 내용과 Embedding 모델이 바뀌지 않은 Chunk는 서버 재시작 시 캐시를 재사용한다.

질문 시 Query Embedding과 Keyword 점수를 결합한 Hybrid 검색을 사용한다. Embedding Provider가 없거나 요청이 실패하면 Keyword 검색으로 자동 전환한다. 최소 점수보다 낮은 Chunk는 Prompt에 넣지 않으며 한 문서의 Chunk가 결과를 독점하지 않도록 문서별 최대 결과 수를 제한한다.

## 상태 확인
/health/live는 프로세스가 요청을 받을 수 있는지 확인한다. /health/ready는 필수 의존성인 MySQL 상태를 확인한다. RAG는 선택적 보강 기능이므로 Keyword 또는 빈 Context의 Degraded Mode여도 채팅 서비스는 시작하며 Health 응답의 rag.status와 rag.mode에서 상태를 확인한다.
